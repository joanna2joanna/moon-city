# 月球盖座城

这是为 Codex 新写的项目 skill。历史反馈已整理到 [项目记忆](references/project-memory.md)，原始记录保存在 [Claude 记忆归档](references/claude-memory-archive.md)。正常制作先读项目记忆；只有需要追溯原话、日期或争议时才读归档。不要同时套用旧 `moon`、`moon-city-lite` 或 `.claude/skills/moon-city.md`。

## 请求与交付范围

- **选题或科学问题**：先查 README 去重并联网核实。默认只提一期，给出标题、核心问题、与近似旧题的边界。用户只是提问时先回答，不自行制作卡片。
- **制作下一期**：选题未定时只确认一次；用户已指定、确认主题或明确让你自选直接做时继续执行，不重复确认。默认一气呵成：资料核实、文案、HTML、文本卡 PNG、README 与索引、配图提示词、AI 视觉成图及验收。不要停在提示词，也不把出图交回用户操作。
- **提示词**：从对应 HTML 提炼，保存并交付可复制的最终文本。只要提示词就到此结束。
- **直接出图**：使用当前可用的图像生成工具，遵循 imagegen skill。完整制卡默认包含出图，不再另问一次；用户只要求给现成卡配图时，保留已确认文案，完成提示词、生成和验收。
- **修订某一期**：记录已确认标题、文案、版式和视觉不变项，只改指定内容。修改标题或主视觉方向须已有明确授权，不能因“更贴切”而静默替换。
- **批量制作或较大改版**：先确认期数、产物范围和时间或生成轮次上限，再开工；默认一期期来。

每次执行命令显式设置项目工作目录。默认项目为 `/Users/joanna/Projects/moon-city`；在本项目的其他检出目录工作时使用当前检出根目录。

## 开始前

读取 `git status --short`、`README.md`、`template-v2.html`、目标期或最近两期 HTML。制作提示词或图片时另读最近三期最终 prompt。核对 README、`issues/`、`review.html` 的期号和标题；有差异先查原因，不擅自补号。

本轮用户要求优先。README 和模板规定当前文本卡结构；项目记忆保留已确认例外及插画规范。旧记录中的事实不是本轮事实来源；规则发生实质冲突且没有明确适用范围时，列出冲突再请用户决定。

## 核实后写作

1. 所有事实先 WebSearch，再打开官方原文、原始论文或机构报告。默认公开、免登录；不读取浏览器凭据，不索要秘密信息。
2. 每个核心数字与因果判断寻找两个独立来源交叉验证，并反向搜索争议、反例、适用条件。同源转载不算独立来源；单篇新研究只能标为该研究的结果，不能写成共识。
3. 数字说明对象、样本、条件、单位和年份。排期只采用官方明确确认的内容，保留“计划”等限定词。核实不了就删去该细节；影响核心结论的分歧必须说明，不能凭用户偏好把证伪内容写成事实。
4. 在 HTML 末尾保存核实注释：日期、关键主张、来源 URL 或 DOI、反向验证、未采用内容。卡面保留 2–3 条真实文献。旧模板里的示例事实和文献全部替换，不作为素材沿用。
5. 按项目记忆检查完整句子、准确术语、视角归属、量词范围和文风。压字数只删冗余表达，保留因果关系与限定词。资料超过 24 小时未使用需重新查询；任务进展等时效信息当天核实。

## 文本卡制作

复用 `template-v2.html`：先复制到新期文件，再用 `apply_patch` 修改内容区。模板 CSS 保持原样；九个全角字标题的既有单卡例外见项目记忆。不复制旧期事实，不重写模板或另造一套生成器。

| 项目 | 验收要求 |
| --- | --- |
| 画布 | 1080×1350，4:5；完整内容位于画布内 |
| 结构 | 顶部四色带、品牌条、系列标签、标题、两个知识块、粉框趣闻、文献、独立免责声明 |
| 标题 | 含“月”，约九个汉字以内，以实际视觉宽度为准，数字不机械等同于汉字宽度 |
| 正文 | 两个知识块各 65–86 字且各三行，趣闻 45–53 字且两行；不为凑字数添加空话 |
| 文风 | 第三人称、零 emoji、准确术语、清楚主语；同一事物不换近义词 |
| 断行 | 无孤字行或一字加标点的尾行；行首无右括号、右引号或不应置于句首的标点，行末无左括号、左引号 |

运行项目现有全检和截图脚本，`NN` 替换为实际文件期号，小于十的期号补零：

```bash
NODE_PATH=/Users/joanna/.workbuddy/binaries/node/workspace/node_modules node check_card.js NN
NODE_PATH=/Users/joanna/.workbuddy/binaries/node/workspace/node_modules node screenshot.js issues/moon-city-NN.html issues/moon-city-NN.png
```

这个 `NODE_PATH` 是当前机器已有依赖位置。换机器先查本地 Playwright；路径不可用时报告具体缺失，不自动装另一套工具。字数定位可用 `python3 count_chars_v2.py issues/moon-city-NN.html`。

**现有校验不能单凭退出码验收。** 当前 `check_card.js` 对超标仍返回零；它打印行数、字数和高度，但没有统一失败判定。`count_chars_v2.py` 的部分范围也与 README 不同。逐项核对实际输出：3/3/2 行、字数、标题宽度、总高度；截图后查看原图，人工补查一字加标点、引用区和裁切。字体加载完成后的渲染结果才有意义。

浏览器启动失败时按运行环境的审批机制处理，不能用静态计数代替渲染验收。本地既有 PNG 只能证明旧截图存在，不能证明本轮 HTML 已通过。

## 收尾

完成 HTML 与提示词后，按项目记忆中的插画规范直接生成 AI 配图并查看。文本卡 PNG 与 AI 插画分别保存，实际核对尺寸、中文、亮度和科学关系；生成失败或中文仍错时明确报告，不能以提示词代替约定的成图交付。

同步 HTML 的网页标题与可见标题、README、review、prompt 的标题和字数描述。`rg` 查旧标题时区分历史归档和本次最终文件，保留旧版不算残留错误。图中若用经用户批准的长标题，记录对应关系。

事实核实后、文本卡验收后、配图交付后各给一条短更新。结束前运行 `git diff --check` 并审查改动范围。报告文件链接、来源、实际检查结果及未完成项，不默认成功。

提交和发布按当前会话已有授权执行；本地制作不自动增加发布权限。已授权就一路完成，不重复询问。只暂存本期文件，避免 `git add -A` 混入其他工作。仓库忽略 PNG，若发布范围包含图片需检查其跟踪状态，仅对已授权的成品显式添加。push 失败只尝试一次，保留本地成果并报告。
