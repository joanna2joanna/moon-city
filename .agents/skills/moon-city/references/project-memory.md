## 文案与事实

- 科学机制句主谓宾完整。分句换主语就写出主语，不让“它”跨句指向多个对象。不用拟人动作代替物理机制。来源：`moon-city-full-svo-science-first`，第 150 期反馈。
- 标题口语化靠句式，测量词和专业名词保持准确。不要用“身高”代替“高程”，不要拆坏专名。来源：`feedback_mooncity_title_precision`。
- 钉住量词、对象和视角：一部分不能写成全部；地球视角与月球视角必须说清。比较时先区分单点极值、全幅差值、平均值和参考基准。来源：`moon-city-avoid-sweeping-ambiguity`、`moon-city-terrain-comparison`。
- 每个核心数字追到原始研究或机构来源，并查反证。历史逸事先核对是否属于正在解释的现象。外部模型的纠错只作线索，采纳前独立核实。来源：`moon-city-data-verification`、`moon-city-issue148-review`。
- 排期区分官方公告、官方媒体转述、专家推算；不把推算窗口写成已确定的日期。核心结论仍站不住的选题不要硬写，可换成证据明确的题目。来源：`moon-city-issue142-review`、`moon-city-issue143-review`。
- 去 AI 味只改词句，不改事实和结构。删二元对比前半句、概括腔和拔高收尾；少用含混的“那份、那点”，不用“咋”“么”替代完整疑问词；避免“要命”等情绪词。破折号默认最多一个，句长有变化。
- 压行数优先删重复与修饰词，不删科学限定词，不把完整术语砍成单字。字数只是初稿参考，最终看实际字体和渲染。

## 版式与已批准例外

- 当前文本卡以 README、`template-v2.html` 为基准。知识块两段各三行，趣闻两行。旧的三知识块、Highlight、Insight 和约五百字正文不再用于新卡。
- 九个全角字的标题若实测溢出，已有用户批准的单卡例外：仅在标题元素加 `style="letter-spacing: 2px;"`，附简短例外注释，模板 CSS 保持不动，重新全检与截图。已在 `issues/moon-city-143.html` 核对到该例外。无需为这个已批准处理再问一次。来源：`moon-city-title-9char-exception`。
- 数字、拉丁字母与汉字不按相同宽度判断；标题字符计数与可用空间分开检查。批准例外仍无法容纳时，报告测量结果再商议，不擅自改标题。
- 结构关系图可在拟题时明确“拓扑”；历史 #127 允许图中长标题与 HTML 紧凑标题配对。这个实例不授权修改其他已确认标题。来源：`moon-city-title-topology`，结合后续标题反馈限定适用范围。
- 不沿用旧 skill 中“高度不足先缩行高和边距”的策略，它与固定模板要求相冲突。先精简冗余内容；确需新布局时提出改版供用户决定。

## 插画与提示词

这里保留 Claude 制图宪章及 #148–150 最终提示词的共同规则；HTML 阅读卡与插画卡有各自布局。不要把旧 Codex `moon` skill 的青色概述和粉框趣味区自动套入插画。

固定视觉：1080×1350、4:5 竖版，画面铺满；顶部黄、粉、青、黄等分细带；居中的黄底黑字小横条“张走走想在月球盖座城”，白细边与粉色偏移阴影；青色系列标签；居中偏上的巨大工业黄标题，粗黑描边与双层洋红投影。标题文字和字数描述相符。

主画面使用非对称构图、三层空间关系、硬朗粗黑结构线和波普粗网点。钴蓝、工业黄、亮洋红承担主要色彩，青色作小标签、白色作正文。用“鲜亮、利落、有光感的印刷漫画”描述整体，暗部只用于必要对比，不堆“死黑、昏暗、微弱”等词。默认不引入橙、棕等暖色；需要特定天体或材料时先核对科学表达，并遵循该期已批准配色。

底部固定左右双栏：左栏工程概览，从本期已核实正文精炼，宪章目标不超过 150 字；右栏数据来源，明确标“参考文献：”，保留本期关键来源。底部独立青色免责声明，原文为“本文为公开信息整理笔记，非严肃学术科普。”提示词可用 Markdown 表示样式，图上不强制印出星号。

提示词依次写画幅、顶部识别、标签与标题、三层视觉、底部双栏、免责声明、色彩质感。使用自然语言描画形状、尺度、位置、颜色、材质和空间关系；画幅声明允许尺寸数字，其余不写 CSS 参数、色号、HTML 类名或“品牌胶囊”。英语或中文沿用用户选择和当前稿件语言。

构图检查：

- 先读最近三期最终 prompt，比对机位、主体、尺度和视觉隐喻，避免连续重复。原始反馈要求先读再写。
- 不用标尺、刻度尺、放大镜、微观颗粒特写；不重复固定“夜空从左上角斜压下来”的场景。
- 痕量或不可见过程不能画成肉眼可见的厚实体层；示意光效不得冒充实际可见现象。检查天体位置、观察点、光照与运动方向。
- 用户已采用的最终提示词才是存档依据，不把早期中文草稿覆盖后期定稿。配图修订先查看目标图，列明不变项与失败点。

完整制卡默认直接出图。先出一个主版本并查看；修改时保留旧版、只修失败点。默认连续修订最多两轮，仍未达标就报告问题和最佳候选，不无限抽图。图像工具的输出分辨率必须实测，提示词写了尺寸不等于结果符合；中文、引用、免责声明、裁切及科学关系逐项检查。任何补字或再排版都要查看最终成品，不交付带错字的“完成版”。

## 工程经验

- 每条命令设置项目目录，写完确认路径。旧 Write 工具要求 Read、用 heredoc 绕开的做法属于 Claude 环境，不迁入 Codex 执行规则。HTML 复用模板，文字编辑用 `apply_patch`。
- `add_review.py` 按卡链接计总数，历史重复卡会导致虚高。检查唯一期号、章节归属和总数；发现旧数据冲突先说明，不能为凑总数随意删卡。来源：`moon-city-add-review-total-trap`。
- 全屏查看器已存在于 `review.html`，`smoke_viewer.js` 也已存在。旧 `moon-city-viewer-todo` 是历史待办，不能再从零造一次。归档中的“1080×1350 是 3:4”为旧笔误，本项目为 4:5。
- 2026-09-11 本地检查：#149、#150 通过现有静态字数工具；原始 #150 PNG 已查看。Playwright 需现有 `NODE_PATH`，本次沙箱启动浏览器报权限错误，因此没有宣称实时渲染通过。这是环境诊断记录，下次须重新检查。
- `check_card.js` 当前只报告问题且以零退出，孤字仅检测末行长度不超过一个字符；未覆盖“一字加标点”等全部要求。不能把“脚本运行完”当成“卡片验收通过”。
- `.gitignore` 忽略 PNG；新图存在于本地不等于已提交。发布图像时检查跟踪状态，不顺手修改整个忽略策略。
